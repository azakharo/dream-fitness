# UI Requirements: DreamFitness

## 1. Общие требования

### 1.1. Платформа и доступность

- **Тип:** Веб-приложение (браузер)
- **Адаптивность:** Адаптивный дизайн для всех устройств (desktop, tablet, mobile)
- **Тема:** Только светлая тема

### 1.2. Технологический стек Frontend

- **Фреймворк:** React + Vite (собственный template)
- **UI Kit:** shadcn/ui (Radix + Tailwind CSS)
- **Платёжная система:** Тинькофф Касса

### 1.3. Цветовая схема

- **Основные цвета:** Зелёные оттенки (свежие спортивные тона)
- Акцент на здоровье, энергии, спорте

---

## 2. Ролевая модель

### 2.1. Роли пользователей

| Роль              | Описание                | Доступ                     |
| :---------------- | :---------------------- | :------------------------- |
| **Клиент**        | Посетитель фитнес-клуба | Клиентский интерфейс       |
| **Администратор** | Сотрудник клуба         | Административный интерфейс |

### 2.2. Разделение интерфейсов

- Единое приложение с разграничением по ролям
- Администратор видит **только** административный интерфейс (без клиентских функций)
- Клиент видит **только** клиентский интерфейс

### 3.1. Клиентская часть

## 4. Страницы клиента

### 4.1. Аутентификация

#### Страница входа (Login)

- Поля: Email, Пароль
- Кнопка «Войти»
- Ссылка «Зарегистрироваться» для перехода к регистрации

#### Страница регистрации (Register)

**Поля формы:**

- Имя (обязательно)
- Email (обязательно)
- Телефон (обязательно)
- Дата рождения (обязательно)
- Пол (обязательно)
- Пароль (обязательно)
- Подтверждение пароля (обязательно)

- Кнопка «Зарегистрироваться»
- Ссылка «Уже есть аккаунт? Войти»

### 4.2. Главная страница (Dashboard)

**Назначение:** Обзор текущего состояния и быстрые действия

**Элементы:**

- Текущий баланс баллов
- Карточка с ближайшими предстоящими тренировками (2-3 шт.)
- Кнопка быстрого перехода к расписанию
- Список последних уведомлений

### 4.3. Расписание тренировок (Schedule)

**Формат отображения:** Календарь (недельный вид)

**Функциональность:**

- Просмотр тренировок по дням недели
- Фильтрация по типу тренировки
- Фильтрация по тренеру
- Клик по тренировке → переход на страницу бронирования

### 4.4. Страница бронирования (Booking)

**Отображение при наличии мест:**

- Информация о тренировке (название, тренер, время, длительность, зал)
- Количество свободных мест
- Стоимость в баллах
- Текущий баланс пользователя
- Кнопка «Записаться»

**Отображение при отсутствии мест:**

- Информация о тренировке
- Статус «Мест нет»
- Текущая позиция в очереди (если уже в очереди)
- Кнопка «Встать в очередь» (если не в очереди)

### 4.5. Профиль (Profile)

**Информация:**

- Имя пользователя
- Email
- Телефон
- Дата рождения
- Пол
- Текущий баланс баллов
- Кнопка «Пополнить баланс»

**Редактирование:** Возможность изменения личных данных

### 4.6. История тренировок (History)

**Содержимое:**

- Список прошедших тренировок
- Список предстоящих тренировок
- Список активных записей в лист ожидания (с указанием позиции)

**Действия:**

- Отмена бронирования (с диалогом подтверждения)
- Выход из листа ожидания

### 4.7. Уведомления (Notifications)

#### Bell icon в хедере

- Индикатор непрочитанных уведомлений (badge)
- Выпадающий список последних 5 уведомлений
- Ссылка «Все уведомления»

#### Страница уведомлений

- Полный список уведомлений
- Возможность отметить как прочитанное
- Фильтрация по типу (бронирование, отмена, транзакции, напоминания)

### 4.8. Пополнение баланса

**Процесс:**

1. Ввод суммы пополнения
2. Переход к оплате через Тинькофф Кассу
3. Возврат в профиль после успешной оплаты
4. Toast-уведомление об успешном пополнении

## 5. Страницы администратора

### 5.1. Dashboard администратора

**Виджеты:**

- Общая статистика загрузки за неделю
- Количество активных клиентов
- Последние действия

### 5.2. Управление расписанием (Schedule Management)

#### Список тренировок

- Таблица с тренировками
- Фильтрация по дате, тренеру, статусу

#### Создание тренировки (отдельная страница)

**Поля формы:**

- Название тренировки
- Тип тренировки (выпадающий список)
- Тренер (выпадающий список)
- Дата и время начала
- Длительность (в минутах)
- Зал (выпадающий список)
- Лимит мест
- Стоимость в баллах

#### Редактирование/удаление тренировки

- Редактирование через отдельную страницу
- Удаление с подтверждением

#### Просмотр записавшихся

- Модальное окно или drawer со списком пользователей на тренировку

### 5.3. Управление пользователями (Users Management)

**Формат:** Таблица с CRUD операциями

**Столбцы таблицы:**

- ID
- Имя
- Email
- Телефон
- Баланс
- Дата регистрации
- Статус (активен/заблокирован)
- Действия (просмотр, редактирование, блокировка)

**Детальный просмотр:** Страница или drawer с полной информацией о пользователе

### 5.4. Отчёты (Reports)

#### Статистика загрузки

- График загрузки по дням/неделям
- Топ популярных тренировок
- Загрузка по залам

#### Финансовые отчёты

- Оборот баллов за период
- Списания по категориям
- Пополнения балансов

## 6. UI-паттерны и компоненты

### 6.1. Состояния загрузки

- **Skeleton loaders** — анимированные плейсхолдеры вместо контента

### 6.2. Пустые состояния (Empty States)

- Иллюстрация/иконка
- Поясняющий текст
- Призыв к действию (кнопка)

**Примеры:**

- «У вас пока нет записей на тренировки» + кнопка «Найти тренировку»
- «Нет уведомлений»
- «Список тренировок пуст» + кнопка «Добавить тренировку» (для админа)

### 6.3. Валидация форм

- Ошибки отображаются **под каждым полем**
- Красная подсветка невалидных полей
- Кнопка отправки неактивна при наличии ошибок

### 6.4. Подтверждение действий

**Модальные диалоги для:**

- Отмена бронирования тренировки
- Удаление тренировки (админ)
- Блокировка пользователя (админ)

**Содержимое диалога:**

- Заголовок
- Описание действия
- Кнопки «Отмена» и «Подтвердить»

### 6.5. Toast-уведомления

**Используются для:**

- Успешное бронирование
- Успешная отмена
- Успешное пополнение баланса
- Ошибки при выполнении операций

## 9. Доступность (Accessibility)

### 9.1. Базовые требования

- Семантическая HTML-разметка
- Поддержка клавиатурной навигации (Tab, Enter, Escape)
- Достаточный контраст текста (WCAG AA)
- Focus-visible состояния для интерактивных элементов
- ARIA-атрибуты для динамических компонентов

### 9.2. Формы

- Ассоциация label с input
- Описание ошибок через aria-describedby
- Обязательные поля помечены \*
